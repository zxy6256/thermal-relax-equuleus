# 02 · 参数取值依据

所有数字都能在 `/data/adb/thermal-relax/config.conf` 里改，改完 `thermalctl apply` 或重启。
下面解释为什么默认是这个值，以及你想改的时候该往哪个方向动。

## 1. 温度标尺：这台机器的四条线

| 参照 | 数值 | 意义 |
|---|---|---|
| SDM845 Tj max | 100~105°C | 硅片绝对上限，到了就是降寿命 |
| 硬件 LMH 介入 | ~95°C | DTB 里 DCVS 开始掐频，我们改不动 |
| 原厂 shutdown 段 | 95 / 100°C | 直接关机，**本模块一行不动** |
| 持续舒适结温 | ≤85°C | 长时间跑在这个温度以下，寿命与功耗都合理 |
| 电池充电上限 | 45°C | 锂电池 45°C 以上充电，容量衰减明显加快 |
| 皮肤/后盖舒适上限 | 43~45°C | 45°C 长时间接触有低温烫伤风险，这是硬上限 |

结论：**软件降频梯子的最高一段落在 84°C，看门狗在 80/86°C 两次机会回滚，硬件 LMH 在 95°C 兜底。**
`MAX_MC=84000` 就是这么来的 —— 它让"放宽"永远停在硬件兜底之前 10°C 的位置。

## 2. 阈值上抬量 `DELTA_MC=8000`（+8°C）

原厂 skin 段第一档 38°C，而握持稳态 37~40°C。要让"正常握着不触发第一档"，至少要 +8°C：

```
原厂   38 / 40 / 42          → 新品一拿起来就触发
+8°C   46 / 48 / 50          → 握持稳态(37~40) 完全落在第一档以下
                             46°C 后盖已经明显发热，但仍在"可手持"带内
```

为什么不再往上：+12°C 会把第一档推到 50°C，那时后盖已经烫手（>46°C 就是大多数人开始
皱眉的区间）。**这是把"体感优先"换成"流畅优先"，代价是机身更热，接受它再调上去。**

## 3. 上限截断 `MAX_MC=84000` 与清阈值让距 `CLRMARGIN=3000`

`thresholds` 和 `thresholds_clr` 都 +8°C，但如果某一段的顶档已经 80°C，+8 就是 88°C ——
已经贴近 LMH。所以对两列都做 `min(v+delta, cap)`：

- `thresholds` 截在 84°C
- `thresholds_clr` 截在 81°C（比触发阈值再低 3°C）

为什么要让 3°C：如果两列被同一个 cap 截断，最后一档会变成
"温度 ≥82 触发 / 温度 ≤82 解除" —— 在 82°C 上下反复横跳，频率跟着抖，反而更卡。
让出 3°C 就是给 step_wise 一个迟滞带。截断本身是单调的（`min(x+d, cap)` 保序），
不会把升序的阈值表打乱，`tests/run_tests.sh` 里有专门的单调性断言。

## 4. 降频下限 `CPU1_FLOOR_KHZ=1209600` / `CPU0_FLOOR_KHZ=1401600`

sdm845 的两张频率表（kHz）：

```
policy0  A55 ×4   300000 576000 787200 998400 1209600 1324800 1478400 1612800 1766400
policy4  A75 ×4   825600 902400 979200 1056000 1209600 1324800 1440000 1536000
                  1612800 1708800 1804800 1900800 2016000 2150400 2265600
                  2400000 2544000 2649600 2803200
Adreno 630        180 257 342 414 520 596 670 710  (MHz)
```

| 下限 | 取值 | 依据 |
|---|---|---|
| A75 | 1209600 (1.2GHz) | 1.2GHz 是 A75 的能效拐点：再低收益很小、性能掉得很快。Android 13+ 的 UI 线程 + 一个前台应用在这个频点上能稳定 60fps |
| A55 | 1401600 (1.4GHz) | 小核要同时扛后台、传感器、音频；低于 1.2GHz 时输入法/通知栏这类短任务会出现明显延迟 |

原厂底的 825600/576000 是给"接近关机保护"用的极端档，被用在 40°C 的日常场景里就是浪费体验。
本模块把**所有** mitigation 档的频率抬到下限以上，但**不动 shutdown 段** —— 过温关机照旧。

> 换平台/换内核时必查：`thermalctl diagnose` → `-- cpufreq --` 里的 `hwmax`。
> 如果 `1209600` 不在你的频率表里，policy 会拒绝写入（无害），但下限也就不生效了。

## 5. 热插拔 `HOTPLUG_RELAX=1`

`actions hotplug` 的 `action_info` 是"关几个核"。原厂常见 `1 2 3`（越热关越多）。
本模块把**除最后一档**外的关核数压到 ≤1：关 2~3 个核对降温的边际收益很小
（关掉的往往是小核），但对唤醒延迟的影响很大。最后一档保留原样，是留给真正过温场景的。

## 6. 调度侧

| 参数 | 原厂常见 | 本模块 | 依据 |
|---|---|---|---|
| `schedutil/rate_limit_us` | 20000 | 5000 | 升频决策延迟 20ms → 5ms。代价是 DVFS 请求变密、功耗略升。低于 5000µs 收益递减，且会和 `uclamp` 的更新周期打架 |
| `schedutil/down_rate_limit_us` | 20000 | 20000（= rate×4） | 降频比升频钝，避免"刚升上去就掉下来"的抖振 |
| `hispeed_freq` | 常缺失 | A55 1.4GHz / A75 1.8GHz | 越过 `up_threshold` 直接跳到这个点，比逐级爬快 |
| `core_ctl/min_cpus`（大核簇） | 1 | 2 | 1 个核时整簇会 power collapse，唤醒要几十 ms；2 个核常驻，代价约 30~60mW |
| `kgsl/thermal_pwrlevel` | 随曲线变 | 0 | 0 = 不受 GPU 温控压制（压制仍由 ④ 层的 gpu 段负责，我们只是不叠加） |
| `kgsl/idle_timer` | 80ms | 110ms | GPU 空闲后多停 30ms 再降频，减少滑动时的档位抖动 |
| `kgsl/devfreq/adrenoboost` | 0 | 1 | 轻度过冲，代价是 GPU 瞬时功耗上升 |

## 7. 兜底参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `GUARD_HOT_MC` | 80000 | 连续 2 个采样周期（20s）≥80°C → 回滚原厂 + 冷却 30 分钟 |
| `GUARD_CRIT_MC` | 86000 | 单次 ≥86°C → 立即回滚（不等第二个周期） |
| `BATT_HOT_MC` | 45000 | 电池 ≥45°C → 立即回滚。电池这条不设迟滞，宁可保守 |
| `GUARD_COOL_MC` | 55000 | 冷却期内跌到 55°C 以下并稳定 60s → 重新放宽 |
| `POLL_SEC` | 10 | 采样周期。10s 一次，CPU 占用可忽略 |
| `COOLDOWN_SEC` | 1800 | 回滚后 30 分钟内不再自动放宽，避免"热了放宽→更热→再回滚"的循环 |

"80°C 结温"这个数看着低，但要理解它是**结温**不是后盖温度：结温 80°C 时后盖大约 44~46°C，
已经到手持上限了。持续 20s 到这个点说明当前使用强度真的把机器压满了，这时候把选择权交回原厂
是正确的。

## 8. 想自己重标定，按这个顺序动

1. **先看现场**：`thermalctl diagnose`，确认 `-- cpufreq --` 里 `hwmax`、`-- thermal zones --`
   里哪几个 zone 在动。
2. **只调 `DELTA_MC`**：先 6000，观察后盖温度与卡顿。满意就停，不满意再加 2000。
   不要一次跳到 12000 —— 你会分不清"更热"和"更流畅"哪个先到极限。
3. **只调 `CPU1_FLOOR_KHZ`**：卡顿集中在"切应用/键盘弹起"就往上抬一档（1324800），
   发热明显就往下退（1056000）。
4. **最后才动兜底线**：`GUARD_HOT_MC` 往上抬之前先想清楚——那是你唯一的手动保险丝。
