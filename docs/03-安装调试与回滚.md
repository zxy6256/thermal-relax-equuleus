# 03 · 安装、调试、回滚

## 0. 前置检查（30 秒，省掉 90% 的"模块没生效"）

```sh
su
getprop ro.product.device        # 期望 equuleus（Mi 8 Pro）
getprop ro.board.platform        # 期望 sdm845
magisk -v                        # 期望 >= 24.0（更早的版本 magic mount 不覆盖 /vendor）
ls -l /vendor/etc/thermal*       # 有没有 thermal-engine*.conf？
ls /data/adb/modules             # 现有模块，确认没有别的温控模块在打架
```

如果第 4 条什么都列不出来，说明这个 ROM 的温控曲线在 HAL 二进制里，模块只剩 sysfs 层
（`thermalctl status` 里会写"配置放宽: 无"）。这种情况先装，再看 `diagnose` 决定下一步。

## 1. 刷入

```sh
# 方式 A：Magisk app -> 模块 -> 从本地安装 -> 选 dist/ThermalRelax-equuleus-v1.0.0.zip -> 重启
# 方式 B：命令行
adb push dist/ThermalRelax-equuleus-v1.0.0.zip /sdcard/
su -c 'magisk --install-module /sdcard/ThermalRelax-equuleus-v1.0.0.zip'
# 重启
```

安装日志里应该出现：

```
- 设备: equuleus / 平台: sdm845
- 扫描 vendor 温控配置…
  ✓ thermal-engine.conf
- 已生成放宽版配置（开机由 magic mount 顶上）
```

## 2. 验证（四条命令，按顺序）

```sh
su -c 'thermalctl status'
```

期望看到：

```
 档位        : relaxed
 温控服务    : vendor.qti.hardware.thermal@2.0-service     ← 或者 thermal-engine
 服务状态    : running
 配置放宽    : 1 个文件
   thermal-engine.conf                已生效               ← 关键：这里必须是「已生效」
 温度
   cpu-1-0-usr       48.2°C
   quiet-therm       39.1°C
 CPU
   policy0  schedutil  cur=1209600 max=1766400 hw=1766400 ok
   policy4  schedutil  cur=1804800 max=2803200 hw=2803200 ok   ← 关键：max 必须等于 hw
 兜底
   hot=80.0°C  crit=86.0°C  batt=45.0°C  cool=55.0°C
   看门狗      : 心跳 3s 前（最热 48.2°C，电池 36.4°C）
```

逐项判读：

| 现象 | 含义 | 处理 |
|---|---|---|
| `配置放宽: 无` | ROM 里没有可放宽的 vendor 配置 | 正常降级运行，只有 sysfs 层 |
| 文件名后面是 `未生效(原厂)` | magic mount 没接住，bind-mount 也没成 | 看日志里有没有 `bind-mount 失败` |
| `max < hw` 且温度不高 | 脏 clamp 没被释放 | `thermalctl release`，仍不行看第 5 节 |
| `看门狗: 无心跳` | `service.sh` 没跑起来 | `thermalctl restart`，再不行看 `log` |
| `温控服务: 未找到 rc 定义` | 该 ROM 的 rc 文件名不规则 | 不影响配置层，但运行时切换要手动重启服务 |

```sh
su -c 'thermalctl log 60'          # 看它到底干了什么
su -c 'thermalctl diagnose'        # 出问题就导这个文件回传
```

## 3. 调参流程

```sh
su -c 'thermalctl config'                       # 看当前值
su -c 'thermalctl set DELTA_MC 10000'           # 想更激进一点
su -c 'thermalctl apply'                        # 立即重建放宽版并顶上去
```

`apply` 会重新跑 `gen_overlay.sh`（用新的 delta 重新生成）→ bind-mount → 重启温控服务，
不需要重启手机。想彻底回到"开机由 magic mount 顶上"的干净状态，重启一次即可。

调参顺序见 [02-参数取值依据.md](02-参数取值依据.md) 第 8 节：**先 DELTA，再 FLOOR，最后才碰兜底线。**

## 4. 日志怎么看

`/data/adb/thermal-relax/log/thermal-relax.log`，一次正常的开机长这样：

```
2026-11-22 16:47:31 === post-fs-data: ThermalRelax v1.0.0 启动 ===
2026-11-22 16:47:31 抓取原厂配置: /vendor/etc/thermal-engine.conf -> /data/adb/thermal-relax/stock/thermal-engine.conf
2026-11-22 16:47:31 已生成放宽版: thermal-engine.conf (conf) stock=9f3c… patched=41ab…
2026-11-22 16:47:31 manifest 已更新，共 1 个温控配置文件
2026-11-22 16:47:33 释放 clamp: policy4 1804800 -> 2803200 kHz
2026-11-22 16:48:12 watchdog 启动 (pid=3821, poll=10s, hot=80000mC, crit=86000mC, batt=45000mC)
```

异常长这样，对应的处理方式写在括号里：

| 日志 | 处理 |
|---|---|
| `配置未被改动（没有可放宽的键）` | 该文件没有 thresholds（可能是另一种格式），拿 diagnose 回传 |
| `放宽版校验失败，保持原厂配置` | awk 输出与原文结构不符，模块自动放弃 —— 这是保护行为 |
| `bind-mount 失败(只读/SELinux)` | 检查 magisk 版本；`chcon` 是否被执行（log 里没有更早的报错就说明是挂载点问题） |
| `【兜底】结温 86000mC >= crit` | 兜底正常工作。想让它更晚触发 → 调 `GUARD_CRIT_MC`，先想清楚 |
| `温度回落稳定，重新放宽` | 冷却期结束，自动恢复放宽 |

## 5. 常见问题

**Q: 装完没变化，`max` 还是被压着**
1. `thermalctl status` 看配置是否"已生效"；
2. `su -c 'cat /vendor/etc/thermal-engine.conf | head -30'` —— 里面 thresholds 应该是抬过的值；
3. 若文件是抬过的但频率仍被压：说明是**框架层或省电模式**在压（`/sys/devices/system/cpu/cpufreq/policy*/scaling_max_freq` 被 PowerHAL 写），关掉省电模式再看。

**Q: 更流畅了但更烫**
这是设计内的交换。往回退一档：`thermalctl set DELTA_MC 6000` + `thermalctl apply`。

**Q: 反而更卡了**
先看是不是 `core_ctl/min_cpus=2` 让大核一直在线、抢了功耗预算：`thermalctl set CORE_CTL_MIN_BIG 1`。

**Q: 充电时特别烫**
充电段（`battery` / `chg-therm`）本模块**一行没动**，充电限流仍由原厂曲线控制。
若仍偏热，那是充电器/线材问题，不在本模块范围。

**Q: 怎么确认它真的降低了卡顿**
不要在"刚重启"时判断（缓存是热的）。用同一路径复现：锁屏 → 等 30s → 解锁 → 立刻上滑进微信 →
观察掉帧。分别记录 `thermalctl stock` 与 `thermalctl apply` 两种状态下同一路径的主观感受，
以及 `dumpsys gfxinfo <包名>` 的 janky frames 数。

## 6. 回滚（三级，从轻到重）

```sh
# ① 软回滚：立刻回原厂温控，模块留着（推荐先试这个）
su -c 'thermalctl stock'
su -c 'thermalctl apply'          # 反悔再切回来

# ② 停用模块：Magisk app 里关掉开关（或 su -c 'touch /data/adb/modules/thermal_relax_equuleus/disable'）后重启
#    所有 overlay / bind-mount 随模块目录一并失效

# ③ 卸载：Magisk app 里移除，或
su -c 'magisk --remove-modules thermal_relax_equuleus'
```

`uninstall.sh` 会停掉看门狗、删掉 `state/` 与 `patched/`，**保留** `log/` 和 `stock/`（原厂配置副本，
方便事后核对）。要清干净：

```sh
su -c 'rm -rf /data/adb/thermal-relax'
```

确认回滚成功：

```sh
su -c 'sha256sum /vendor/etc/thermal-engine.conf'
su -c 'cat /data/adb/thermal-relax/state/overlay.manifest'   # 卸载后这个文件应该不存在
su -c 'thermalctl status'                                     # 应该是 command not found
```

## 7. 出问题时的最小信息集

把这三样贴出来，基本就能定位：

```sh
su -c 'thermalctl diagnose'                  # /sdcard/Download/thermal-relax-diag-*.txt
su -c 'thermalctl log 200'
su -c 'cat /data/adb/thermal-relax/config.conf'
```

`diagnose` 里已经包含：thermal zone 全表、cooling device、每个 policy 的频率/调速器/schedutil
参数、kgsl 全部关键节点、core_ctl、HAL 服务列表、原厂 vs 放宽版的 diff、manifest、配置、日志尾。
