# 01 · 这台机器上"温度"是怎么变成"降频"的

先看清链路，才知道该动哪一层。Mi 8 Pro（equuleus）跑 LineageOS 时，从传感器读数到
`scaling_max_freq` 被压低，中间要过五道关，只有两道是用户态能碰的。

## 1. 五层结构

```
┌─ ① 传感器 ─────────────────────────────────────────────────────────────┐
│  TSENS / PMIC ADC，暴露成 /sys/class/thermal/thermal_zoneN/{type,temp}  │
│  sdm845 上常见: cpu-0-0-usr cpu-0-1-usr cpu-1-0-usr cpu-1-1-usr         │
│                 gpuss-0-usr quiet-therm xo-therm pop_mem pa-therm0      │
│                 batt / chg-therm（走 power_supply）                     │
└────────────────────────────────────────────────────────────────────────┘
                              ↓
┌─ ② 硬件 LMH（DTB 里，改不动） ─────────────────────────────────────────┐
│  qcom,lmh-dcvs：结温逼近 ~95°C 时由 DCVS 硬件直接掐频，绕过一切软件      │
│  /sys/class/thermal/cooling_device*/ 里能看到对应实例                   │
│  → 这是最后一道物理兜底，也是"放宽不会烧"的真正原因                     │
└────────────────────────────────────────────────────────────────────────┘
                              ↓
┌─ ③ 内核 thermal zone + cooling device（trip point 在 DTB，只读） ───────┐
│  policy: step_wise / power_allocator；trip 点在设备树里，sysfs 只读     │
│  能读能看，改不了 trip                                               │
└────────────────────────────────────────────────────────────────────────┘
                              ↓
┌─ ④ vendor 温控策略（★ 可写，主要战场） ────────────────────────────────┐
│  A. 老路：/vendor/bin/thermal-engine + /vendor/etc/thermal-engine*.conf │
│     段格式 [SS-xxx] / [MONITOR-xxx]:                                   │
│       sensor / thresholds / thresholds_clr / actions / action_info      │
│     actions = cpu    → action_info 是一串 kHz，直接写 scaling_max_freq │
│     actions = gpu    → 写 kgsl 的 pwrlevel                             │
│     actions = hotplug→ action_info 是"关几个核"                         │
│     actions = shutdown → 直接关机（千万别动）                          │
│  B. 新路：QTI Thermal HAL (AIDL) 读 /vendor/etc/thermal_info_config.json│
│     阈值写在 HotThreshold / VrThreshold 数组里                          │
└────────────────────────────────────────────────────────────────────────┘
                              ↓
┌─ ⑤ 框架 / perfd（影响"卡不卡"，不是"降不降"） ─────────────────────────┐
│  schedutil 的 rate_limit_us / hispeed_freq、core_ctl 的热插拔、         │
│  kgsl 的 idle_timer / adrenoboost、PowerHAL 的 input boost              │
└────────────────────────────────────────────────────────────────────────┘
```

## 2. 只有两层可写

| 层 | 可写性 | 本模块怎么用 |
|---|---|---|
| ① 传感器 | 只读 | 只看。看门狗就靠它 |
| ② LMH | 不可写（DTB） | 不动。它是兜底 |
| ③ kernel trip | 不可写（DTB） | 不动 |
| ④ vendor 策略 | **可写（文件）** | magic mount 顶掉配置文件；`thermalctl` 可运行时切回 |
| ⑤ 调度/GPU 参数 | **可写（sysfs）** | `service.sh` 开机铺一次，看门狗每 60s 复检 |

所以任何声称"解除温控"的模块，能做的只有 ④ 和 ⑤ —— ②③ 改不了，这也正是它们还能兜住的原因。

## 3. 为什么 Lineage 给人的感觉"过于保守"

三条独立原因叠在一起，症状都长一个样：**摸起来不烫，但就是掉帧**。

1. **原厂曲线是照"体感温度"设计的，不是照"结温"**
   Xiaomi 的 `[SS-SKIN]` 段 `sensor quiet-therm`（后盖附近）阈值常见 38/40/42°C。
   玻璃后盖在 25°C 室温下握持的稳态温度本来就在 37~40°C —— 也就是说，
   **手机刚拿起来就已经站在第一档 mitigation 上了**。这不是 bug，是产品目标（不烫手）与
   Lineage 用户目标（流畅）的冲突。

2. **mitigation 阶梯的底部太低**
   sdm845 原厂配置的 `action_info` 会一路压到 `825600`（A75）/`576000`（A55）。
   在这两个频点上跑 Android 13+ 的 UI 线程，必然掉帧。而阶梯是 step_wise 逐级下降的，
   一旦落到低档，`thresholds_clr` 又要等温度掉 2°C 才回升 —— 于是"卡一下、顺一下"。

3. **调度侧本来就钝**
   `schedutil/rate_limit_us=20000` 意味着最快 20ms 才评估一次升降频；
   大核簇 `core_ctl/min_cpus=1` 允许整簇 power collapse，唤醒要几十毫秒。
   这两条与温控无关，但和"偶尔卡顿"高度相关（尤其是清后台、切应用、输入法弹起那一瞬）。

## 4. 本模块的三个介入点

```
④ vendor 策略   thresholds +8°C（上限 84°C 截断）
                thresholds_clr 再多让 3°C（防抖振）
                action_info 频率下限 1.2GHz/1.4GHz
                hotplug 关核数收敛到 ≤1（最后一档保留原样）
                ── 电池/充电/功放/shutdown 段：一行不动
⑤ sysfs         schedutil rate_limit 5000µs、hispeed_freq 抬高
                core_ctl/min_cpus=2（大核簇不掉电）
                kgsl thermal_pwrlevel=0、idle_timer 110ms、adrenoboost=1
⑤ 脏状态        每 60s 巡检 scaling_max_freq，温度不高却被压 → 释放
```

## 5. 一次"卡顿"被修掉的全过程

```
拿起手机（quiet-therm 39°C，原厂曲线已经在第一档）
  → 原厂: scaling_max_freq 被压到 1.6GHz，点开微信 + 键盘弹起
  → schedutil 20ms 才升一次频，大核簇还在 power collapse
  → 掉 3 帧
本模块:
  → quiet-therm 39°C 落在新阈值(46°C)之下，第一档根本不触发
  → 万一触发，最低也只到 1.4GHz/1.2GHz，UI 线程够用
  → rate_limit 5ms、大核簇常驻 2 核在线，键盘弹起时频率已经在位
```

## 6. 什么时候这个模块帮不上忙

- ROM 把温控曲线编进了 HAL 二进制（没有 `thermal-engine*.conf`）：只剩 ⑤ 层
- 卡顿来自 I/O（`cfq` 队列）或 lmkd 杀进程：与本模块无关，看 `thermalctl diagnose` 里的
  cpufreq/内存段再判断
- 电量低于 15% 且开了省电模式：框架层会强制 `schedutil` 上限，和温控无关
